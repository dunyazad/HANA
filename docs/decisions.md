# HANA 설계 결정 기록

사용자가 확정한 결정을 순서대로 기록한다. 각 결정의 설명과 예시는 `docs/language.md`에 있다.
결정을 바꾸면 이 목록과 `docs/language.md`를 함께 고친다. `[초안]`은 확정 전의 세부안, `[미정]`은 아직 정하지 않은 것이다.

1. 기본 틀은 JSON을 확장한 문법이다 (B안). JSON의 구조(객체, 배열, 값)를 유지하면서 사람이 쓰기 편하게 넓힌다.
   - 따옴표 없는 키를 허용한다. [초안] 주석, 끝 쉼표 허용
   - [초안] 값 자리에 식을 쓸 수 있다 (`enabled: count > 0`, `increment: count = count + 1`)
   - [초안] 객체 앞에 종류 이름을 붙일 수 있다 (`button { text: "+1" }`)
   - 표준 JSON의 상위 집합이다. 모든 표준 JSON 파일은 그대로 올바른 HANA 소스다. 따옴표 있는 키와 없는 키를 모두 허용한다.
   - [미정] HANA 소스를 순수 JSON으로 변환하는 기능
2. 대상 범위: GUI부터 일반 로직, 시스템 프로그래밍까지 전부를 이 JSON 확장 문법 하나로 다룬다.
3. 모든 선언은 `이름: 종류 { 키: 값 }` 형태의 객체다. 함수는 두 가지 표기를 모두 허용한다.
   - 객체형: `fib: fn { in: { n: i64 }, out: i64, do: ''' ... ''' }`
   - 짧은 머리 표기: C++ `std::function<int(int)>`과 같은 모양 `fn<반환타입(인자)>`
     - `double: fn<i32(x: i32)> x * 2`
     - 반환값이 없으면 `void`를 생략한다: `scale: fn<(inout p: v3, k: f32)> p = p * k`
     - 여러 값 반환: `divmod: fn<(i32, i32)(a: i32, b: i32)> (a / b, a % b)`
     - 함수 타입(콜백 등)도 같은 표기: `on_damage: fn<(amount: i32)>`, `compare: fn<bool(a: T, b: T)>`
     - [초안] 제네릭 함수의 타입 매개변수는 이름 쪽에 붙인다: `max<T>: fn<T(a: T, b: T)> ...`
   - 객체형 함수의 본문도 같은 규칙으로 `do: ''' ... '''`에 쓴다.
4. 실행 코드(문장 목록)는 `'''` 코드 블록에 쓴다.
   - `'''...'''`는 문자열이 아니라 "코드 값"이다. 컴파일러가 파싱하고 검사한다. 일반 문자열은 `"..."`.
   - 닫는 `'''`의 들여쓰기만큼 각 줄 앞 공백을 제거한다.
   - 한 줄짜리 식이나 문장 하나는 따옴표 없이 쓴다 (`enabled: count > 0`, `on_click: count = 0`, `scale: fn<(inout p: v3, k: f32)> p = p * k`). 여러 줄 코드만 `'''`로 감싼다.
   - 한 줄 본문은 `,`, `}`, `]` 또는 줄바꿈에서 끝난다. 괄호 안의 쉼표는 본문의 일부다.
   - 값 자리(`enabled`)와 동작 자리(`on_click`)는 같은 모양이지만, 컴파일러가 그 키가 기대하는 타입으로 구분한다. 값 자리에 대입문을 쓰면 오류다.
   - 반환 타입이 있는 함수의 한 줄 본문은 그 식의 값이 반환값이다.
   - 순수 JSON으로 바꾸면 코드 블록은 문자열 하나가 된다.
   - 편집기 지원(언어 서버)은 `'''` 안을 코드로 인식해야 한다.
5. `'''` 안쪽의 블록은 Python처럼 들여쓰기로 나눈다.
   - [초안] 블록을 여는 줄은 `:`로 끝난다 (`if n < 2:`, `while i < 3:`). 본문이 한 문장이면 같은 줄에 쓸 수 있다 (`if n < 2: return n`).
6. 3D 그래픽스용 수학 타입을 기본 제공한다. 처음에는 `v2`, `v3`, `v4`, `m33`, `m44`로 시작하고, 나머지(`quat`, `v3i`, `v3d`, `m43` 등)는 필요할 때 추가한다.
   - 기본 수학 타입은 키워드가 아니라 표준 라이브러리의 기본 가져오기(prelude)에 둔다. 사용자가 같은 이름을 정의하면 사용자 것이 우선하므로, 타입을 추가해도 기존 코드가 깨지지 않는다.
   - [초안] 원소는 `f32`, 행렬은 열 우선(column-major)
   - [초안] 벡터 `+ - * /`는 성분별, `m * v`와 `m * m`은 행렬 곱, 내적/외적은 `dot`/`cross` 함수
   - [초안] swizzle `.xyz`, `.rgba`
   - [초안] 기대 타입이 벡터인 자리의 JSON 배열 `[1, 2, 3]`은 그 벡터가 된다
7. 사용자 정의 타입은 표준 라이브러리 타입과 같은 지위를 갖는다. 이를 위해 `struct`와 연산자 오버로딩을 둔다.
8. 실행 방식: 네이티브 컴파일 (LLVM). 개발 중 빠른 실행은 JIT로 보완한다.
9. 타입 검사: 정적 타입 + 추론. 추론할 수 있으면 타입 표기를 생략한다 (`var i = 0`).
   - [초안] 기본 숫자 타입 `i8`~`i64`, `u8`~`u64`, `f32`, `f64`, 그 외 `bool`, `str`
10. 메모리: GC 없음. RAII + 이동(move) 기본 + `unsafe` 영역에서만 원시 포인터.
11. 주석: `'''` 코드 블록 안에서는 `#`, 바깥 JSON 부분에서는 `//`와 `/* */` (JSON5와 같은 방식).
12. 제어문과 논리 연산자 (`'''` 안): Python 표기를 따른다.
    - `if`/`elif`/`else`, `while`, `for x in xs`, `break`, `continue`, `return`, `match`
    - 논리 연산자 `and`, `or`, `not`
    - [초안] `match`의 갈래는 `패턴: 본문` (`Circle(r): return 3.14159 * r * r`)
13. 에러 처리: `Result<T, E>` 값과 `?` 연산자. 예외는 없다.
14. 모듈: 파일 하나 = 모듈 하나. 최상위 객체의 `use` 키로 가져오고 (`use: ["std.io", "gui"]`), 공개할 이름 앞에 `pub`을 붙인다 (`pub area: fn ...`).
15. 반응형 상태: 어떤 객체에서든 `state` 키에 넣은 값은 반응형이다. 그 값을 읽는 식(`text: f"Count: {count}"`, `enabled: count > 0`)은 값이 바뀌면 자동으로 다시 계산된다. `app` 전용이 아니라 사용자 `component`에도 똑같이 쓰인다.
16. 함수 인자 전달 방식: 참조 타입은 없다. 표시 없음은 읽기 전용(복사 없음), `inout`은 호출자의 값을 수정, `sink`는 소유권 이동. 인자는 함수 밖에 저장할 수 없다. 호출하는 쪽은 `inout` 인자에 `&`를 붙인다 (`scale(&pos, 2.0)`).
17. 타입 확장: 제네릭(`List<T>`)과 `trait`(`Shape: trait { area: fn<f32(self)> }`). 클래스 상속은 없다.
18. 문자열 보간은 `f"..."`로만 한다 (`f"Count: {count}"`). 일반 문자열 `"..."` 안의 `{ }`는 글자 그대로다. 표준 JSON 문자열의 의미가 바뀌지 않게 하기 위함이다.
19. `null`은 `Option<T>`의 "값 없음"이다. 아무 타입에나 들어갈 수 있는 값이 아니다.
    - [초안] `match`에서 `Some(n)` / `null` 갈래로 나눈다
20. 변수 선언: `let`(불변), `var`(가변). 선언 없는 대입은 오류다.
21. struct의 메서드는 struct 객체 안에 함수 키로 둔다. `self`도 인자 전달 방식을 따른다 (`self` 읽기, `inout self` 수정, `sink self` 소유권 이동). `self`가 없는 함수는 `Player.new("A")`처럼 타입 이름으로 부른다.
    - [초안] 필드 기본값 `hp: i32 = 100`
22. 클로저: 이름 없는 함수도 `fn<...>`로 쓴다 (`fn<bool(p: Player)> p.alive()`).
    - 캡처는 기본 읽기. 수정은 `[inout total]`, 소유권 이동은 `[sink conn]`을 앞에 붙인다.
    - 함수 밖에 저장하는 클로저(이벤트 핸들러, 다른 스레드로 넘기는 클로저)는 모든 캡처가 `sink`여야 한다.
23. enum은 경우마다 데이터를 가질 수 있다. `match`는 모든 경우를 다뤄야 하며 빠지면 컴파일 오류다.
    - 패턴: 경우와 바인딩 `Circle(r)`, 나머지 `_`, 리터럴, 범위 `1..=9`, 조건 `n if n > 100`
    - `match`와 `if`는 값을 돌려주는 식으로도 쓴다.
24. 복사: 값은 기본 이동. 숫자, `bool`, 수학 타입은 `Copy`. 사용자 타입은 `Point: struct copy { ... }`처럼 표시해야 `Copy`. 그 밖의 복제는 `.clone()`.
25. `unsafe`: 원시 포인터 `*T`(읽기), `*var T`(쓰기)는 `unsafe` 안에서만 만들고, 역참조하고, 산술한다. `unsafe`는 함수 전체 또는 코드 블록 일부(`unsafe:` 들여쓰기 블록)에 붙인다. 숫자 변환과 주소에서 포인터로의 변환은 `as`.
    - [초안] 함수 전체 표시 위치 `fn<(address: usize, value: u32)> unsafe: true '''...'''`
26. C/C++ 연동
    - C 함수 선언은 `extern "c"`, HANA 함수 공개는 `export "c"`, C와 같은 메모리 배치는 `layout: "c"`.
    - C 헤더는 컴파일러가 libclang으로 직접 읽어 가져온다 (`use: ["c:stdio.h"]`, 사용 `c.printf(...)`).
    - C++은 도구가 C 인터페이스 접착 코드를 자동 생성해 시스템 C++ 컴파일러로 빌드하고 함께 링크한다 (`use: ["cpp:physics.hpp"]`).
      - 일반 함수, 네임스페이스: 자동 바인딩
      - 템플릿이 아닌 클래스: HANA struct로 감싸고 생성자/메서드/소멸자를 연결한다. C++ 소멸자는 HANA RAII로 자동 호출된다.
      - enum, POD 구조체: 그대로 대응
      - 템플릿: 설정에 적은 인스턴스(`std::vector<float>` 등)만 바인딩 생성
      - 예외: 경계에서 잡아 `Result`의 에러로 바꾼다
      - C++ 클래스를 HANA에서 상속하는 것은 지원하지 않는다
    - C/C++ 동적 라이브러리(DLL, .so, .dylib)는 세 방식을 모두 지원한다.
      1. 빌드할 때 연결: `hana.json`의 `link`에 적으면 실행 시 OS가 불러온다.
      2. 실행 중 불러오기 + 헤더: `library { name: "physics", load: "lazy" }`. 처음 호출할 때 불러오고 `available()`로 확인한다.
      3. 실행 중 불러오기, 헤더 없음: `Library.open(...)`, `lib.symbol<fn<...>>("add")`. 호출은 `unsafe`, 실패는 `Result`, 해제는 RAII.
      - [초안] 위 표기들
      - C++ 클래스를 내보낸 DLL은 헤더로 만든 접착 코드가 필요하다(1, 2번). 접착 코드는 DLL과 같은 종류의 컴파일러(MSVC 또는 GCC/Clang)로 빌드한다. 3번은 `extern "C"` 함수만 가능하다.
27. 동시성 1단계: OS 스레드 + 채널 + `Mutex<T>`. 스레드에 넘기는 값은 `sink` 캡처, 스레드 간 전달 가능 타입은 컴파일러가 검사한다. `async`/`await`는 나중에 정한다.
28. 표준 라이브러리: `core`(OS 없이 동작), `std`(파일, 스레드, 네트워크, 시간), `platform`(창, 입력), `gui`, `gfx`(3D). GPU 계층은 WebGPU (네이티브 Dawn, 웹 Emscripten).
29. `'''` 코드 블록은 중첩하지 않는다. 코드 블록 안의 클로저 본문은 들여쓰기 블록으로 쓴다.
    - [초안] `spawn([sink tx] fn:` 다음 줄부터 들여 쓴 본문
30. 사용자 정의 연산자는 이름으로 된 중위 연산자로 만든다 (`dot: infix fn<f32(self, o: v3)> ...`, 사용 `a dot b`).
    - 우선순위는 하나로 고정: 함수 호출보다 약하고 비교 연산자보다 강하다.
    - 기호로 새 연산자를 만드는 기능은 두지 않는다. 나중에 꼭 필요하면 기존 우선순위 단계에 붙이는 제한된 형태로만 검토한다.
    - [초안] 기존 타입에 메서드/연산자를 더하는 `v3: extend { ... }`
31. 숫자 리터럴: 표준 JSON 숫자(지수 포함)에 `0xff`, `0b1010`, `1_000_000`, 접미사(`10u8`, `7i64`, `2.5f32`)를 더한다. 접미사 없는 정수는 `i32`, 소수점/지수가 있으면 `f64`가 기본이고, 기대 타입이 있으면 그 타입이 된다.
32. 정수 오버플로: 디버그 빌드는 panic, 배포 빌드(`-O`)는 감싸기(wrap). 의도적인 경우는 `wrapping_add`, `saturating_add`, `checked_add`(`Option` 반환). 0으로 나누기는 항상 panic.
33. 컬렉션: `str`(소유하는 UTF-8 문자열, 문자열 타입은 하나), `List<T>`, `Array<T, N>`, `Map<K, V>`, `Set<T>`. JSON 배열은 `List`(기대 타입이 `Array`면 `Array`), JSON 객체는 기대 타입이 `Map`이면 `Map` 값이 된다.
34. 연산자 오버로딩: 따옴표 키에 기호를 써서 정의한다 (`"+": fn<Money(self, other: Money)> ...`). 대상은 산술, 비교(`==`, `<`에서 나머지를 자동 생성), 첨자 `[]`, 복합 대입(정의하지 않으면 이항 연산자에서 자동 생성).
    - `and`, `or`, `not`은 오버로딩할 수 없다. `and`/`or`의 짧은 평가가 모든 타입에서 같게 동작하도록 하기 위함이다. 식을 조립하는 DSL은 `&`, `|`를 오버로딩한다.
35. 패키지 설정 파일: 순수 JSON인 `hana.json`.
36. 튜플: 타입 `(i32, i32)`, 값 `(a, b)`, 분해 `let (q, r) = ...`, 위치 접근 `.0`, `.1`. 원소가 모두 `Copy`면 튜플도 `Copy`. 순수 JSON으로 바꾸면 배열이 된다.
37. 출력: prelude의 `print`(줄바꿈 붙임)와 `write`(줄바꿈 없음). 숫자, `bool`, `str`, 수학 타입, 출력용 trait을 구현한 사용자 타입을 출력한다. 실수는 값을 되살릴 수 있는 가장 짧은 표기로 출력한다 (`0.30000000000000004`, `2.0`).
38. 값을 돌려주는 `if`는 Python식 삼항식 `a if cond else b`다. 여러 줄에 걸친 값 선택은 `match`를 쓴다.
39. 들여쓰기: 공백만 허용하고 탭은 컴파일 오류다. 한 블록 안에서 같은 깊이를 지키면 칸 수는 자유다. 포매터(`hana fmt`)는 2칸으로 맞춘다.
40. `usize`/`isize`는 포인터와 같은 폭의 정수다 (길이, 인덱스, 주소). `char`는 유니코드 문자 하나(32비트), 리터럴 `'a'`. 작은따옴표 하나는 `char`, 세 개는 코드 블록이다. 문자열은 큰따옴표만 쓴다.
41. 여러 줄 `'''` 블록의 들여쓰기 기준은 첫 코드 줄이다. 코드를 닫는 `'''`보다 더 들여 써도 되고, 닫는 `'''`보다 덜 들여 쓴 줄과 첫 코드 줄보다 덜 들여 쓴 줄은 오류다 (결정 4 보완).
42. 타입 표기 없이 리터럴로 초기화한 변수(`var i = 0`)는 그 함수 안에서 처음 타입이 정해지는 곳(인자, 타입 있는 값과의 연산, 대입, 반환)의 타입을 따른다 (Rust 방식). 정해지지 않으면 `i32`/`f64`, 서로 다른 타입으로 쓰이면 오류다. 암묵적 변환은 여전히 없다.
43. inout 배타성: 같은 호출에서 겹치는 자리(`p`와 `p.x`)를 inout으로 두 번 넘길 수 없다. `Copy`가 아닌 값은 inout으로 넘기면서 같은 자리를 다른 인자나 받는 값(`self`)으로도 넘길 수 없다. `Copy` 값을 읽는 인자는 호출 전에 복사되므로 inout 자리와 겹쳐도 된다 (`t.hit(t.hp)`, `f(&x, x)`).
44. 데이터가 없는 enum 경우는 `Red: {}`로 쓴다. 표준 JSON 그대로이고, 데이터가 있는 경우 `Circle: { radius: f32 }`와 모양이 같다.
45. enum 값은 이름 있는 필드로 만든다: `Shape.Circle { radius: 1.0 }`. 데이터가 없는 경우는 `Color.Red`.
46. `match` 패턴: 경우와 바인딩 `Circle(r)`(필드 선언 순서대로 위치에 맞춤), 나머지 `_`, 정수/문자/bool 리터럴, 범위 `1..=9`와 `1..10`, 조건 `n if n > 100`, 이름 바인딩 `n`. `match`는 문장으로도, 값을 돌려주는 식(`let x = match v:`)으로도 쓴다.
47. 필드를 이동하면(`let n = p.name`) 그 필드가 속한 변수 전체가 이동된 것으로 본다. 부분 이동은 없다. 값을 나눠 가지려면 분해(`let (a, b) = p`)나 `match`를 쓴다.
48. `Option<T>` 값: `Option<T>`가 기대되는 자리에 `T` 값을 쓰면 자동으로 `Some`이 된다 (`let a: Option<i32> = 5`). 직접 쓸 때는 `Some(5)`. 값 없음은 `null`.
49. `Option<T>`의 짧은 표기 `T?`를 둔다. `i32?`와 `Option<i32>`는 같은 타입이다. 타입 자리의 `?`는 식의 `?` 연산자(결정 13)와 다르다.
50. `Option` 값은 `x == null`, `x != null`로 비교할 수 있다. 값을 꺼내는 것은 `match`의 `Some(n)` / `null` 갈래로 한다. 기본값 연산자나 `unwrap_or` 같은 메서드는 제네릭과 표준 라이브러리와 함께 정한다.
51. 소멸자: struct/enum 안의 `drop: fn<(inout self)>` 키. 값이 범위를 벗어날 때 자동으로 불리고 직접 부를 수 없다. 본문이 끝난 뒤 필드가 자동으로 해제된다. 변수는 선언의 역순으로 해제된다. `copy` 타입은 `drop`을 가질 수 없다.
52. `.clone()`: `str` 같은 표준 타입은 기본으로 갖는다. struct, enum, 튜플, `Option`은 모든 필드가 clone 가능하면 자동으로 갖는다. 사용자가 `clone: fn<Self(self)>`를 정의하면 그것을 쓴다. `drop`이 있는 타입은 자동으로 만들지 않는다.
53. `str` 기본 기능: 연결 `a + b`와 `+=`, 비교 `==` `!=` `<` `<=` `>` `>=`(바이트 순서), `.len()`(바이트 수, `usize`), `f"..."`를 값으로 어디서나 쓴다.
54. 필드 해제 순서: `drop` 본문이 끝난 뒤 필드는 선언의 역순으로 해제된다 (C++과 같음, 변수와 같은 규칙). 튜플 원소도 역순이다.
55. `List<T>` 첨자 `xs[i]`는 필드처럼 자리다: 읽기, 대입 `xs[i] = v`, 그 자리에서 수정 `xs[i].hp -= 1`, inout 전달 `&xs[i]`. 범위 밖이면 panic. `Copy`가 아닌 원소는 첨자로 꺼내 이동할 수 없다 (`.clone()`, `pop()`, `remove(i)`를 쓴다).
56. `for` 원소 받기는 인자 전달 방식(결정 16)을 따른다: `for x in xs` 읽기, `for inout x in xs` 그 자리에서 수정, `for sink x in xs` 원소를 소유하고 `xs`는 이동된다. 반복하는 동안 `xs`는 바꿀 수 없다.
57. 첨자와 길이의 타입은 `usize`다. 타입 없는 리터럴 변수는 첨자로 쓰이면 `usize`로 추론된다.
58. `List<T>` 기본 기능: 값 `[1, 2, 3]`, 빈 값 `[]`(기대 타입 필요), `len()`, `is_empty()`, `push(sink v)`, `pop() -> T?`, `insert(i, sink v)`, `remove(i) -> T`, `clear()`, `.clone()`, 자동 해제. 원소는 어떤 타입이든 된다.
59. 제네릭 타입 매개변수는 이름 키에 쓴다: `Pair<T>: struct { ... }`, `Maybe<T>: enum { ... }`, `max<T: Ord>: fn<T(a: T, b: T)>`. 쓸 때는 `Pair<i32>`이고, 값과 인자에서 타입 인자를 추론한다 (`Pair { first: 1, second: 2 }`, `max(3, 7)`).
60. 타입 매개변수의 trait 제약은 매개변수 옆에 쓴다: `T: Ord`, 여러 개는 `T: Ord + Clone`.
61. 타입이 구현하는 trait은 타입 안의 `is` 키로 표시한다: `is: [Shape, Show]`. 메서드는 그 타입 안에 그대로 정의하고, 컴파일러가 빠진 메서드와 모양이 다른 메서드를 검사한다.
62. 제네릭 본문은 정의할 때 한 번 검사한다. 본문에서는 제약이 허락하는 것만 쓸 수 있고, 오류는 제네릭 정의 쪽에서 난다. 코드는 쓰인 타입마다 따로 만든다 (단형화). 동적 디스패치(trait 객체)는 이후에 정한다.
